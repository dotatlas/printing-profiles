# Printing Profiles

An open-source website for sharing 3D printing slicer presets. A Go API, a Next.js frontend, and PostgreSQL.

## Layout

```
api/                 Go module: main.go, internal/<pkg>/ (one level), migrations/, queries/, openapi.yaml
web/                 Next.js app (TypeScript): app/ (routes, layout, theme), components/, lib/ (API reads, generated types)
bruno/               API collection: one request per route, with assertions
deploy/              self-hosting: compose.yml (db, migrate, api, cloudflared; web as a profile), env file examples, update and backup scripts with their systemd units
brand/               logo.png: the master logo (2048 px, transparent); every logo file of the site is cut from it
docker-compose.yml   local PostgreSQL
.env.example         every environment variable, with placeholders
```

## Commands

```bash
docker compose up -d                 # local PostgreSQL (port 5432)
go -C api run . migrate              # apply the migrations in api/migrations
go -C api run . serve                # run the API (dev defaults; see .env.example)
go -C api run . start                # migrate, then serve, in one process (for hosts that run one process)
go -C api vet ./...
go -C api test -race ./...           # Go tests; integration tests need the database, -short skips them
cd bruno && npx @usebruno/cli run --env local   # API checks against the running API
docker build -t printing-profiles-api ./api       # container image (runs "serve" on port 8080)
docker run --rm -v "$(pwd -W)/api:/src" -w /src sqlc/sqlc:1.31.1 generate   # regenerate api/internal/db from api/queries (Git Bash: prefix MSYS_NO_PATHCONV=1)
npm --prefix web ci                  # install the site's packages, exactly as locked
npm --prefix web run dev             # run the site on http://localhost:3000
npm --prefix web run lint
npm --prefix web run typecheck
npm --prefix web test                # Vitest + Testing Library
npm --prefix web run gen:api         # regenerate web/lib/api-types.ts after api/openapi.yaml changes
docker build -t printing-profiles-web ./web       # site image (port 3000; set API_URL; runs with --read-only)
docker compose -f deploy/compose.yml config --quiet   # check the production stack (env files in CONFIG_DIR, default /etc/printing-profiles)
```

## Conventions

- **Go:**
  - `gofmt` and `go vet` clean. Errors are wrapped with `%w` and returned, never ignored.
  - `api/internal/db` is generated by sqlc: change `api/queries/*.sql` and regenerate, never edit the Go files by hand.
  - `context.Context` first. No global mutable state.
  - SQL only through sqlc-generated, parameterized queries.
  - Schema changes only through new goose migrations. Never edit an applied one; add first, remove in a later release.
- **API:**
  - Routes live under `/api/v1/`, and each is documented in `api/openapi.yaml`.
  - Errors use RFC 9457 problem details. Lists use cursor pagination.
- **TypeScript:**
  - `strict`, no `any`.
  - API types are generated from `api/openapi.yaml`, never written by hand.
  - Server components for public data. Client components only where interaction needs them.
  - Colors only from the theme tokens in `web/app/globals.css` (`page`, `ink`, `muted`, `line`, `accent`), never raw values. Each token has a light and a dark value. The palette doesn't depend on the logo: any logo must look right on it, and the logo can change without a palette change.
  - The logo files in `web/app` are cut from `brand/logo.png`, trimmed to the drawing: `logo.png` 96 px (header), `icon.png` 192 px, `apple-icon.png` 180 px on white (iOS paints transparency black), `favicon.ico` 16/32/48 px, `opengraph-image.png` 1200x630 (logo, name and tagline on white). Cut them again when the logo changes.
- **Comments:**
  - Every function and method gets a one-line doc comment: what it does, and how it relates to other functions.
  - Comments inside functions are sparse, only where a line isn't obvious.
  - All comments are in ASD-STE100 Simplified Technical English: short sentences, one meaning per word, active voice.
- **Tests:**
  - Write the test first and watch it fail. Commit it with the code it tests.
  - Go integration tests use a real Postgres in Docker.
  - Every write route has a test proving a stranger is refused.
  - Every route has a Bruno request.
- **Security:**
  - Never commit secrets (`.env` is ignored).
  - npm installs only versions at least 7 days old, with exact pins (`web/.npmrc`).
  - Validate input at the API boundary.
  - Check authorization on every write.
  - Never store passwords (sign-in is GitHub or Discord OAuth, or a one-time email link).
  - Sign-in and sessions:
    - Store tokens only as SHA-256 hashes. The session cookie is `__Host-session` (HttpOnly, Secure, SameSite=Lax).
    - Find users by (provider, provider user ID), never by email.
    - Return paths go through `safeReturnPath`.
    - Every POST, PATCH and DELETE needs the site's `Origin` and a JSON body (`checkWrites`).
    - The fake provider and the log mailer exist only with `ENV=dev`.
  - Never log tokens, session IDs or personal data.
  - Validate uploads by their content, never their file name.
- **Deploy** (`deploy/`):
  - No service publishes a port; the tunnel is the only way in. The `data` network is internal, so the database has no internet.
  - Every service is read-only, drops all capabilities, has `no-new-privileges`, a memory limit and rotated logs.
  - Secrets live only in the env files on the host (root only, mode 600), never in the repo. The `*.env.example` files hold placeholders.
  - Scripts are POSIX `sh` and pass shellcheck.
- **Commits:**
  - Conventional Commits (`feat: ...`, `fix: ...`), lowercase, no emojis, no trailing period.
  - One logical change per commit: the code together with its tests, API contract, Bruno requests and docs. Aim for about 100-400 changed lines; split bigger changes by logical part.
  - Every commit builds and passes the tests where it stands.
- **CI** (`.github/workflows/ci.yml`) runs these checks on every push to `main` and every pull request, with a read-only token:
  - Third-party actions are pinned by full commit SHA, with the version in a comment. Pick releases that are at least 7 days old.
  - Tools that CI downloads (govulncheck, Redocly, the Bruno CLI) are pinned to exact versions.
  - On a push to `main`, after both checks pass, the `Images` job builds the API and site images and pushes them to `ghcr.io/<owner>/<repo>/{api,web}`, tagged with the commit and `main`. It is the only job with write access (`packages: write`).
